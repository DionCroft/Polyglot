# Intel CPU package — 12 October 2026

Target: Windows 11 x64, Intel Core i5-1035G1, 16 GB RAM. Device identifiers are not
required for compatibility or included in this report. The development host is a
Snapdragon X ARM64 PC; Windows x64 tests on this host use emulation.

## Changes

0.7.2b1 Intel CPU package revision 1 adds Launch-CPU.cmd and a --cpu startup flag.
On x64 it selects Fast and CPU before the first readiness check. Other platform
startup defaults and all speech/translation models remain unchanged. Existing
microphone, language, vocabulary, presets and voice preferences are retained.
No changes were made to audio segmentation, recognition/translation algorithms,
Auto thresholds, thread counts or overlays. The unrelated accelerators.py whitespace
edit is excluded from the commits.

## Checks

Six startup cases failed before the startup selector existed. Tests now cover saved
GPU/NPU/Auto preferences, keeping teaching preferences and stored settings intact,
other-platform defaults, and CPU selection never constructing an accelerator worker.
Both Windows suites pass **146 tests with two POSIX-only skips**: native ARM64 and
x64 under ARM emulation. The source x64 CPU-start UI check passes real English and
Mandarin WAV recognition/translation, language/preset switching, pause/resume,
transcript saving, completed-caption visibility and muted real English voice playback.
It verifies CPU was selected before warm-up despite saved Intel NPU settings.

## Final Windows x64 executable

Built from `e1bb19b87de7d9359482ae4ef05c715ef1a45cdf`; the next commit `4b6fb2e`
only corrects the Windows simulation in a regression test on native macOS. Application
and packaging sources are identical between those commits. The initial Mac CI test
failure was a missing platform mock, not a change to macOS accelerator selection.

All six packaged checks pass: English/CO7000, both conversation directions, CPU-start
UI, CPU Auto replay, Auto UI, and system speech output. PE architecture is verified
as x64. The startup UI test deliberately saves Intel NPU first and verifies Fast/CPU
is warmed before the lecture. All 29 locked model files match their SHA-256 hashes.
Speech and translation outputs in the English/conversation packaged checks exactly
match the previous 0.7.2b1 x64 package; no new accuracy claim is made.

Four saved sessions recover byte-for-byte in all six TXT/SRT/VTT exports. The real
35.38-second CPU Auto WAV replay completes seven bilingual pairs in English → Mandarin
→ English order, with no dropped audio, dropped phrases or skipped translations.
Three uncertain-language phrases are correctly withheld; this short test does not
establish reliable detection of every phrase in class.

Sampled peak process-tree working set was approximately 1.55 GB for the CPU-start UI
check and 1.33 GB for the CPU Auto replay. These are short x64-emulated runs on this
host, not memory guarantees or measurements on the Intel laptop. Other packaged
checks exercised the existing DirectML backend on Adreno, not Intel graphics.
English voice tests are muted; actual audibility/pronunciation require feedback.
The source UI screenshot was visually checked for layout and visible controls.
